# ルール作製(プロジェクト固有 rule の追加)

> rules は「対象ファイルを読んだ瞬間に効く**書き方の規範**」。ADR(なぜの履歴)とは独立して保管し、相互リンクは持たない(rule に `ADR-NNNN` を書かない)。

## 手順

1. **出力先の判断**: 既存 rule(`.claude/rules/*.md`)に同じ領域があれば**追記**する(プロジェクト固有の意味ルールは `conventions.md` が既定の受け皿)。無い場合だけ新設する。
2. **paths の設計(新設時)**: そのルールが効くべきファイルを `paths:` グロブで表す。
   - **paths を決められない規範は rule にしない**(発火しない rule = 参照されない文書)。近縁の rule に節として吸収する。
   - 対象がまだ存在しない新設場面(プロジェクト・フォルダの新規作成)向けには、上位の広い rule に 1 行のポインタを置く。
3. **重複・矛盾チェック**: 既存 rules と矛盾しないか、同じ規範の再掲にならないかを確認する。矛盾する場合は人に確認して片方へ寄せる。
4. **記述の規律**: 書き方の規範だけを簡潔に(1 rule 目安 50 行)。背景・経緯は書かない(それは ADR の領域)。正の記述で規定する。`.editorconfig` / analyzer で機械強制できるものは rule に書かない。
5. **発火確認**: paths がこのプロジェクトのフォルダ規約・命名と整合しているか確認する。

## 書式

```markdown
---
paths:
  - "**/Services/**"
---

# <規範のタイトル>

- <規範 1>
- <規範 2>
```
