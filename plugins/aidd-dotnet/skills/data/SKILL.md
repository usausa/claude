# DB / データアクセス規約

> .NET 共通の原則。**採用 ORM / DB はアーキ固有**なので、採用形態の rule の「データの具体」を参照。

- **ORM / データアクセス方式は用途で選定する。EF Core を既定としない** (Micro-ORM・生 SQL も対等な選択肢)。選定は `/adr` に残す。
- テーブル名・カラム名は **PascalCase** (オブジェクトマッピングを簡略化)。
- 監査・追跡用途の列 (更新日・更新者) を業務ロジックに使わない。業務上の日付が要るなら別カラムを定義。
- 列挙値のカラムは、文字自体に意味が無ければ TEXT でなく **INTEGER**。
- **SQL で表示用加工・構造変換をしない**。SQL は効率的なクエリに専念し、加工は上位で行う。
- パラメータは文字列連結でなく**バインドパラメータ**を使う。SQL インジェクションを作らない。
- **LIKE 検索は必ずエスケープ**する (ユーザー入力の `%` `_` を素通ししない。DB 依存のエスケープ・重複判定は方言ヘルパーに隔離)。
- 一意制約は**事前 SELECT せず INSERT して重複だけ判定**する (競合に強く、コードが短い。扱いは `errors` skill)。
- データアクセスのメソッド命名 = **動詞 + 対象 + 形状 + Async**: `QueryXxxAsync` = 単一 (null 許容) / `QueryXxxListAsync` = `List<T>` / `QueryXxxEnumerableAsync` = `IAsyncEnumerable<T>`。
- **トランザクション境界は Service / Usecase 層**。データアクセス層は tx を受け取るだけ (自分で張らない)。tx 参加メソッドは**第 1 引数に `DbTransaction`** を取り、取らないメソッドは auto-commit。複数操作・採番・ロックを伴うときだけ明示 tx。
- モデルは 3 分類: `XxxEntity` (テーブル 1:1 の写像) / `XxxView` (SELECT 結果の読み取り専用) / `動詞XxxParameter` (検索条件・更新の入力)。
- 旧式 DB の型癖 (`'1'/'0'` 文字列 bool、`yyyyMMdd` 文字列日付) は**型変換の境界で吸収**し、ドメイン側は .NET の型 (`bool` / `DateTime`) を使う。
- SQL を外部ファイルで書く方式を採る場合は、**素の SQL としてそのまま実行できる形**を保つ。
