# コーディング原則 (.NET 共通)

> .NET 共通の不変原則 (全形態で同一)。書式は `.editorconfig` + analyzer が正。
> プロジェクト固有で編集する方針 (analyzer で機械化できないもの) は プロジェクトの `.claude/rules/conventions.md` に置く。

## 命名
- 省略形は避ける (`usr`→`user`)。同じ概念に同じ名前を一貫して使う。DB 命名は `data` skill。

## 設計の指針
- DRY / SOLID / YAGNI。早期リターンでネストを浅く。
- 上位層 (UI / エンドポイント) は薄く保ち、ロジックは下位層 (Service / Domain) へ委譲する。
- 汎用処理はヘルパー / ユーティリティへ。ただしアプリ・ドメイン固有の共通処理は Domain へ。
- 時刻は `DateTime.Now` を直参照しない。業務の処理日時はリクエスト / 処理単位のコンテキストに**確定値として保持して参照**し (同一処理内で時刻を揺らさない)、「今」を確定する境界は `TimeProvider` を注入してテストで差し替え可能にする。

## メンバ記述順序
- ① 定数 → ② フィールド (static → インスタンス) → ③ イベント → ④ プロパティ → ⑤ コンストラクタ (+ Dispose) → ⑥ ライフサイクルメソッド → ⑦ メソッド群 → ⑧ ネスト型。
- メソッド群は public/private の順より**処理の種類単位のグルーピング**を優先し、`//----` 区切りでセクション化してよい。関連メンバの近接配置 (フィールドとプロパティの対 等) は優先してよい (analyzer で機械強制しない)。

## DI 登録
- 登録は機能単位の `AddXxx()` 拡張メソッドにまとめ、合成ルート (Program / Application) は 1 行呼ぶだけにする。機能専用の設定バインドも同じ拡張に同居させてよい (機能の自己完結)。
- 同一インターフェースの実装群は列挙登録し、利用側は `IEnumerable<IXxx>` で受ける。

## ビルド / 品質 (警告抑止の三層)
- ビルド警告ゼロが完了条件。抑止は三層で使い分け、適用前に人へ確認する。
  - `Analyzers.ruleset` = ソリューション全体・全プロジェクト共通のルール強度。**層依存の規則は含めない**。
  - `GlobalSuppressions.cs` = プロジェクト単位の恒久抑止。**層依存の規則はここで無効化する** (例: `CA2007` は Web ホスト・Worker・テスト等のアプリ側プロジェクトで抑止し、共通ライブラリでは抑止しない。`CA1305` / `CA1416` 等もプロジェクト単位で必要になったときに検討)。
  - `#pragma warning disable/restore` = 局所抑止 (範囲を最小に)。`[SuppressMessage]` には Justification を書く。

## テストを仕様として書く
- 受け入れ条件はテスト名に意味を込める。手書きの現状仕様は作らず、テストが実行可能な仕様になる。
